### T-01 — Edited applied migrations (checksum drift) {#t-01}

| Field        | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

[CORRECTED 2026-09-17 · [V-02](../validation/LOCAL_VALIDATION_LOG.md)]                                                                                                                                                                                                                                        |
| Cause        | Already-created migration files were edited after the fact: `prisma/migrations/0_init/migration.sql` (latest change in commit `185afc9`, 2026-09-15, 34+/33−; project notes date the rewrite 2026-09-12) and `prisma/migrations/202608120003_shared_project_tracking/migration.sql` (commit `6572a99` "Fix Prisma validation and migration replay", 2026-09-12, +60 lines). Earlier reports describe `0_init` as **empty** (`project-docs/MIGRATION_INTEGRITY_REVIEW.md`, `FIX_COMPLETION_REPORT.md`). The checksum stored in `_prisma_migrations` on existing (shared/production) databases no longer matches, but Prisma 7.9.1 `deploy`/`status` do not act on it, so the drift is invisible (`prisma migrate dev`, not used in deploy, is expected to flag it — not tested). |

A schema diff of the live DB shows none of the objects added by the edited migrations missing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Evidence     | `prisma/migrations/0_init/migration.sql`, `git log -- prisma/migrations/0_init`, `package.json` `build` script, user memory note "0_init was rewritten 2026-09-12 — shared/prod database needs `migrate resolve` before its next deploy" (the `migrate resolve` requirement is refuted for Prisma 7.9.1). ### T-07 — `403 Request origin is not allowed.`

| Field        | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Problem      | Any `POST/PUT/PATCH/DELETE` to `/api/*` returns 403 JSON `{ "error": "Request origin is not allowed." }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Cause        | `proxy.ts` rejects state-changing API requests whose `Origin` header is missing or differs from both the request origin and `APP_URL`. Typical triggers: reverse proxy/TLS terminator changes host/scheme so `request.nextUrl.origin` ≠ browser origin and `APP_URL` is unset or has a trailing slash/path; server-to-server clients (curl, Postman, mobile apps, **webhook providers**) that send no `Origin`.                                                                                                                                                                                                                               |
| Resolution   | Set `APP_URL` to the exact browser origin (e.g. `https://app.example.com`, no trailing slash). Browse at exactly `APP_URL` (see T-25). For manual API testing send a matching `Origin` header. Razorpay/Persona webhooks (`POST /api/webhooks/*`) send no `Origin` and **are blocked** by the proxy: locally, POST without `Origin` → 403 before the handler, with the `APP_URL` Origin → 401 invalid signature (handler reached); `Authorization: Bearer` requests without `Origin` are also 403 [VALIDATED 2026-09-17 · [V-20](../validation/LOCAL_VALIDATION_LOG.md)]. Live provider delivery `[NEEDS VALIDATION — not testable locally]`. |
| Verification | Mutation succeeds from the browser; `curl -X POST -H "Origin: <APP_URL>" …` no longer 403.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Evidence     | `proxy.ts:4-14,44-46,102-104`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

### T-17 — Inconsistent rate limiting

| Field        | Detail                                                                                                                                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
