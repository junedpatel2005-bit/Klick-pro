# Non-Functional Requirements (implementation-derived)

Last verified against code: 2026-09-16 (commit cd8f4fb); runtime-validated 2026-09-17

This document lists quality attributes **only where the repository shows evidence** (configuration, library usage or handler logic). Each NFR records whether the code **enforces** it. Expectations with no implementation evidence are listed separately in §12, "Not evidenced / gaps", so they are not mistaken for delivered qualities.

**Conventions**

- **ID:** `NFR-<CAT>-NNN`. CAT ∈ SEC, PERF, AVAIL, SCAL, OBS, USAB, A11Y, I18N, COMP, MAINT, PORT.
- **Enforcement:** `Enforced` (active in code or config for all relevant paths) · `Partial` (active on some paths only, or weakened) · `Config-dependent` (active only when environment variables are set) · `Not enforced` (defined but not applied).
- Related: [SRS.md](./SRS.md), [functional-requirements.md](./functional-requirements.md), [../08-operations/security.md](../08-operations/security.md), [../03-architecture/authentication-and-authorization.md](../03-architecture/authentication-and-authorization.md).
