# 16.10 Admin APIs & Dashboard Backend

## Purpose

Give administrators a secure command center for marketplace operations, moderation, finance, CMS, support, and activity monitoring.

## Implemented work

- Role-protected admin API routes and dashboard.
- User and verification management.
- Job, proposal, project, dispute, and support oversight.
- Service category and CMS management.
- Finance, wallet, and payout visibility.
- Admin notification center for client registrations, professional registrations, job posts, and proposals.
- Historical admin notification backfill so older activity is visible.

## How to explain it

The admin module has full marketplace visibility, but it is protected by the Admin role. It helps the operations team review activity, resolve issues, approve verification, and manage content without directly changing the database.

## Detailed administration design

The administration backend is an operational layer rather than a normal user dashboard. It aggregates marketplace information that is distributed across users, jobs, proposals, projects, payments, verification records, support requests, and CMS pages. Each administration route must verify the Admin role on the server before returning data or allowing a mutation.

The dashboard provides high-level counts for operational awareness. Dedicated pages support more specific tasks: Users for account review, Verification for trust/safety review, Jobs & disputes for marketplace issues, Finance for wallet and payout oversight, Support for customer requests, CMS for content editing, and Notifications for platform activity.

Admin notifications provide a chronological audit-style activity feed. New client registrations, professional registrations, published jobs, and proposals are recorded. The backfill process ensures older records can also be shown, so the notification screen is not empty immediately after the feature is introduced.

## Operational controls

- Administrative routes are unavailable to normal client and professional sessions.
- Job detail and user detail views retrieve real database information rather than relying on only card summaries.
- Admin actions should be logged or traceable so operational changes can be investigated.
- Financial actions require careful status handling and should never be triggered only by a frontend button state.
- CMS preview and public-page publishing should be separated so unreviewed edits do not accidentally become public.

## Presentation example

Explain the admin dashboard as the marketplace control center. It does not replace the database; it provides secure, validated screens and APIs for staff to monitor and manage real records.

## Demonstration

1. Sign in as an administrator and open `/admin`.
2. Show Users, Verification, Jobs & disputes, Finance, Support, CMS, and Notifications.
3. Open `/admin/notifications` to show current and historical events.
4. Create a job or proposal from another account and confirm that the admin receives a new notification.
