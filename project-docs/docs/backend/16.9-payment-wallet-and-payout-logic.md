# 16.9 Payment / Wallet & Payout Logic

## Purpose

Track project money safely through milestones, wallet balances, commission fields, and professional withdrawal requests.

## Implemented work

- Milestone and transaction data records.
- Wallet balance calculation based on completed/approved work.
- Commission-related fields for marketplace fees.
- Professional earnings view.
- Validated withdrawal requests that cannot exceed available balance.
- Administrative visibility into finance and payout records.

## Production requirement

The internal payment and wallet workflow is implemented with Razorpay Checkout and Razorpay Route. Live money collection, refunds, and bank payouts still require test credentials, verified webhooks, Route activation, and production compliance setup.

## Detailed money flow

Payment logic is connected to the project and milestone lifecycle. A project can contain one or more milestones, each with a defined amount and completion state. When client approval makes a milestone eligible for payment, the backend records the transaction and uses those records to calculate professional earnings and wallet availability. Platform commission fields keep marketplace revenue separate from the professional’s payable amount.

A withdrawal request is not just a screen action. The backend checks the authenticated professional, calculates or reads available balance, validates the requested amount, and rejects requests that exceed available funds. Administrators can review requests and use the finance area to track the payout process.

## Why external payments are separate

Internal financial records describe what the marketplace believes is due. A provider such as Stripe or Razorpay actually moves money. A production payment integration must create provider payment objects, verify signed webhooks, handle failed/duplicate events, reconcile provider state with database transactions, and follow regional tax, KYC, and payout requirements.

## Safe production sequence

1. Select Razorpay or Stripe based on the business country and payout needs.
2. Configure test API keys and webhook secret in environment variables.
3. Create payment intents/orders only on the server.
4. Mark payment status from verified webhook events, not from frontend success messages.
5. Test refunds, cancellations, duplicated webhooks, and insufficient-balance withdrawal cases.

## Demonstration

1. Create or open an accepted project.
2. Approve a completed milestone.
3. Open the professional Earnings/Wallet page.
4. Create a withdrawal request within the available balance.
5. Open the admin finance area to show the recorded request.
