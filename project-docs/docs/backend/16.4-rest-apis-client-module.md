# 16.4 REST APIs - Client Module

## Purpose

Allow clients to manage their account, jobs, proposals, projects, files, and wallet activity through protected APIs.

## Implemented work

- Client profile and account endpoints.
- Job creation, editing, publishing, closing, and job-detail retrieval.
- Proposal review, acceptance, and rejection actions.
- Project milestone actions, work review, and file access.
- Verification, dashboard, wallet, and payment-related endpoints.
- Input validation before data is accepted by the server.

## How to explain it

The client API module is the backend layer behind the client dashboard. It verifies that the current account owns the job or project before allowing a change.

## Detailed client workflow

The client starts by managing profile and verification data. The main marketplace workflow begins when the client creates a draft job. The job includes title, category, description, work mode, budget, location, priority, and deadline. When published, it becomes visible to eligible professionals and the backend creates notifications for those professionals and administrators.

Professionals submit proposals against the job. The client sees only proposals for jobs they own and can compare professional information, price, delivery expectation, and proposal content. When the client accepts one proposal, the backend performs a controlled state transition: it accepts the selected proposal, handles competing proposals according to the business rule, creates the project records, and changes the job from open to its appropriate active/closed state.

During delivery, client endpoints expose project progress, milestone values, messages/files where implemented, and review actions. The client can approve work or request changes. Each sensitive action checks both the current role and the project ownership relationship.

## API safeguards

- Server-side input validation prevents invalid job budgets, statuses, or identifiers.
- Ownership checks prevent one client from reading or editing another client’s records.
- State checks stop invalid transitions, such as accepting a proposal for an already closed job.
- Notifications are triggered after successful marketplace actions, not before the database operation completes.

## Presentation example

Explain the client module as the “demand side” of the marketplace. The client creates work demand, evaluates offers, starts the project, and releases progress through milestone review. The API is responsible for making those actions secure and consistent.

## Demonstration

1. Sign in as a client.
2. Create and publish a job.
3. Open received proposals and accept or reject one.
4. Open the project and milestone information after accepting a proposal.
