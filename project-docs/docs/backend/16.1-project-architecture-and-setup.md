# 16.1 Project Architecture & Setup

## Purpose

Provide a maintainable application foundation for the client marketplace, professional workspace, and administrator portal.

## Implemented work

- Next.js 16 application using App Router routes.
- Separate client, professional, and admin areas with reusable layout components.
- Shared server libraries for authentication, database access, validation, notifications, and realtime events.
- API route structure separated by domain such as jobs, proposals, projects, payments, files, and administration.
- Environment-based configuration for database, secrets, email, OAuth, maps, storage, and payment providers.
- Project scripts for development, linting, type checking, formatting, and project-flow validation.

## How to explain it

The project is organized by responsibility. Pages display the UI, API routes handle requests, shared libraries hold business logic, and Prisma connects the application to PostgreSQL. This makes the system easier to extend without mixing frontend and backend logic.

## Detailed architecture

Servio uses a layered architecture. The presentation layer contains public pages and role-specific dashboards. The application layer contains API endpoints and server actions that receive validated requests. The domain layer contains reusable code for marketplace rules, such as creating notifications, checking ownership, calculating wallet availability, and creating project records. The persistence layer uses Prisma to translate application queries into PostgreSQL operations.

This separation is important because the same business rule can be used from many pages. For example, when a proposal is accepted, the server can create a project, update proposal status, update job status, create notifications, and return a consistent response. The client page should not be trusted to perform these actions by itself.

The application has three role-specific experiences:

- Client: creates jobs, reviews proposals, manages active projects, and tracks payments.
- Professional: manages services and profile, finds jobs, submits proposals, completes milestones, and tracks earnings.
- Admin: monitors users, verification, jobs, disputes, finance, support, CMS, and platform notifications.

## Request flow

1. A user opens a page and the UI loads data from the protected backend endpoint.
2. The endpoint reads the signed session and identifies the current user and role.
3. The endpoint validates input, runs authorization and business checks, then reads or writes PostgreSQL data through Prisma.
4. If the action creates marketplace activity, the notification service saves notification history and sends a realtime event.
5. The endpoint returns only the data that the role is allowed to see.

## Quality and deployment controls

- Environment variables keep secrets out of source code.
- TypeScript helps detect invalid data shapes during development.
- ESLint and Prettier maintain code consistency.
- Prisma migrations make database changes repeatable across environments.
- The custom Node server hosts Next.js and Socket.IO together for realtime delivery.

## Demonstration

1. Run `npm run dev`.
2. Open the client dashboard, professional dashboard, and `/admin`.
3. Show the shared header, footer, sidebar, and route separation.
4. Run `npm run lint` and `npm run typecheck`.
